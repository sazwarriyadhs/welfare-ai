# WELFARE AI - FEATURE STATUS DEFINITIONS

| Status | Meaning | Required evidence |
|---|---|---|
| Planned | Approved product scope, not started | Product specification |
| Under Evaluation | Feasibility or requirements being validated | Evaluation notes |
| In Development | Active implementation | Source code and task reference |
| Implemented | Feature code exists | Code review and implementation evidence |
| Tested | Acceptance and relevant tests passed | Test results |
| Released | Approved deployment/release | Release record |
| Deferred | Intentionally postponed | Decision and rationale |

## Important Rules

- A folder is not an implementation.
- A README is not a working feature.
- A mockup is not a working feature.
- A successful build does not prove business acceptance.
- A vendor reference model does not prove integration support.
- AI model output does not prove clinical or welfare validity.
- A test must have defined expected results.

Feature status must be tracked at feature level, not only module level.
